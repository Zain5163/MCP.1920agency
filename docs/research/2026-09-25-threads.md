# Threads — corrects an earlier wrong assumption

**Date:** 2026-09-25
**Why:** this note exists because a claim was made without checking, and it was wrong.

## The mistake

Threads was described as "almost free to add, it is the same Meta app". The
reasoning was that Meta owns Threads, so it must be behind the Graph API.

**It is not.** The correction was made publicly and in the roadmap, and it is the
reason RULES.md R7 exists.

## VERIFIED

- Threads lives at **`graph.threads.net`**, not `graph.facebook.com`.
- It has **its own OAuth**, its own scopes (`threads_basic`,
  `threads_content_publish`), and needs a Meta app configured for the **Threads
  use case** — a different configuration, not a different permission.
- A long-lived token lasts **60 days and MUST be refreshed between 24 hours and
  60 days**. Outside that window it is simply dead and the account must be
  reauthorised from scratch.
- Unlike Instagram, Threads **can post text alone**.

That refresh window is why the `refresh` runner and the Windows scheduled task
exist at all. A Facebook Page token does not expire while the app stays
installed; a Threads token dies quietly, and posts start failing weeks later with
a credential error that points at nothing.

## Token exchange

Short-lived first, then long-lived. Skipping the second exchange yields a
credential that dies within the hour — which looks like a successful connect
until the next day.

## NOT CHECKED

Text limit (500 assumed), media counts, video length. All still `verified: false`
in `capabilities.ts`.

## Status

Adapter and provider built and unit-tested. **Never published for real** — needs a
Meta app with the Threads use case and its own credentials, which do not exist yet.
